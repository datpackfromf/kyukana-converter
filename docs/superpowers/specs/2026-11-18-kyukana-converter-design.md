# 旧かな変換Webページ 設計書

日付: 2026-11-18

## 目的と背景

現代仮名遣いで書いた短い文（主にXへの投稿）を、スマホのブラウザだけで歴史的仮名遣い（旧かな）に直し、そのままコピーまたはXの投稿画面に渡せるようにする。入力文は端末の外に出さない。

成功の条件: 公開URLをスマホ幅で開き、入力 → リアルタイム変換 → コピー／Xで投稿 が一続きで動くこと。変換できない所を「直したふり」をしないこと。

- やること: 仮名部分の現代→歴史的仮名遣いへの変換、未確認箇所の明示、コピー、Xの投稿インテント、Xの数え方での文字数表示、小書き→大書きオプション（初期ON）。
- やらないこと: 旧字体への変換、漢字の読み替え、サーバー処理、アカウント機能。
- 失敗とみなすこと: 入力文の外部送信。根拠のない推測変換（辞書にない語を規則外で書き換える）。スマホで操作できない画面。

## 制約

- 静的サイト（GitHub Pages）。ビルドは Vite のみ。
- 形態素解析もブラウザ内で動かす。
- 依頼者への質問はしない。判断は `docs/decisions.md` に記録する。

## 方式の検討（Approaches）

形態素解析器（数値は 2026-11-18 に手元で計測。詳細は decisions.md）:

| 案 | 配信サイズ | 初期化 (Node, PC) | ライセンス | 品詞・活用型・活用形・読み |
|---|---|---|---|---|
| A. lindera-wasm-web-ipadic 2.0.0 | wasm 13.1MB（gzip 11.9MB） | 約165ms | MIT（IPADICは同梱ライセンス） | 取れる（IPADIC形式） |
| B. kuromoji.js 0.1.2 | 辞書 .dat.gz 合計 17.8MB | 約379ms | Apache-2.0 | 取れる（IPADIC形式） |
| C. Sudachi WASM (sudachi-wasm333) | パッケージ 125MB | 未計測（サイズで除外） | Apache-2.0 | 取れる |

採用: **A（lindera）**。同じIPADICで出力は同等、配信量が最小、初期化が最速。B は最終更新が2016年で配信量も大きい。C はスマホで読み込める大きさではない。

変換方式:

1. 規則だけで変換 — 漢語や「ゐ・ゑ・を」は規則で決まらず、誤変換が出る。不採用。
2. 単語辞書だけで変換 — 活用形の数だけ辞書が要り、助動詞・活用語尾の体系的な変化を扱えない。不採用。
3. **解析 → 規則 → 辞書 の3層（採用）** — 活用語尾・助動詞は規則で、語の中身は出典付き辞書で決め、どちらでも決まらない所は変えずに「未確認」として示す。

## 全体構成

```
index.html            画面（1ページ）
src/main.js           画面の動き（入力・表示・コピー・X投稿・文字数）
src/analyzer.js       lindera の読み込みとトークン正規化
src/engine/kana.js    かな操作（ひら/カタ変換、段の変換、小書き→大書き）
src/engine/rules.js   規則層
src/engine/dict.js    辞書層（data/dict.json の索引化と検索）
src/engine/convert.js 3層をまとめる変換本体（解析器は引数で受け取る＝テスト可能）
src/engine/count.js   Xの数え方での文字数
data/dict.json        現代仮名→歴史的仮名の辞書（出典付き）
tests/cases.json      入力→期待値（50件以上）
tests/*.test.js       node:test によるテスト
docs/                 decisions.md, sources.md, 設計書, 計画
```

エンジンは解析器を引数で受け取る純粋な関数にし、Node のテストでもブラウザでも同じ lindera パッケージ（web版を `initSync` で初期化）を使う。

## 変換エンジン

### 入力と出力

`convert(text, { smallToLarge = true })` → `{ output, segments }`。
`segments` は `{ text, status }` の並びで、`status` は `kept`（変更なし・確認済み）/ `converted`（変換した）/ `unverified`（判定できず原文のまま）。

### 0層: 解析と前処理

- lindera(IPADIC) で分かち書きする。lindera 2.0.0 は `conjugationType` と `conjugationForm` が入れ替わって返るため、アダプタで正規化する（「段」「型」「特殊・」を含む方を活用型とみなす）。
- 未知語（UNK）は値が `undefined` になるので空文字として扱う。
- **辞書の最長一致による再分割**: ひらがなの並びで、解析器のトークン開始位置から辞書の語（`scan: true` の語、3文字以上）が、解析器のトークンより長く一致する場合は辞書の語を1語として採用し、残りを解析し直す（例: 「きょう|は|ゆう|がたから」の「ゆうがた」、「ちょうちょ|う」の「ちょうちょう」）。

### 1層: 規則

根拠は docs/sources.md（文化庁「現代仮名遣い」付表 ほか）。

1. **ワ行五段動詞（IPADIC 活用型「五段・ワ行促音便」「五段・ワ行ウ音便」）の活用語尾**: 語尾の最後の1字を `わ→は, い→ひ, う→ふ, え→へ, お→は` に置き換える（言わ→言は、言い→言ひ、言う→言ふ、言え→言へ、言お→言は）。促音便「っ」はそのまま（大書きオプションで「つ」）。
2. **意志・推量の「う」の直前**: 次のトークンが助動詞「う」のとき、直前のトークンが **五段動詞・形容詞・助動詞** で、末尾がオ段なら同じ行のア段に（書こ→書か、よかろ→よから、だろ→だら）、末尾が「しょ」なら「せ」に（でしょ→でせ、ましょ→ませ）。**一段・サ変・カ変（考えよ・しよ・来よ）は対象外**（「見よう」は歴史的仮名遣いでも「見よう」— 付表）。
3. **形容詞の連用ゴザイ接続（ウ音便）**: 基本形の語幹（末尾「い」を除く）＋「う」にする（うれしゅう→うれしう、早う→早う）。語幹が辞書で変わる場合は辞書を優先。
4. **助動詞語幹**: 名詞・非自立/特殊/接尾 の助動詞語幹「よう」→「やう」、「そう」→「さう」（ようだ→やうだ、降りそうだ→降りさうだ）。意志の助動詞「よう」は変えない。
5. **助詞・助動詞の閉じた一覧**: は・へ・を・が・に・で・と・の・も・か・や など、歴史的仮名遣いでも同じ形の助詞・助動詞は「確認済み・変更なし」とする（一覧は `src/engine/rules.js`、出典は sources.md）。「くらい／ぐらい」「ずつ」など変わる語は辞書で扱う。
6. **小書き→大書き（オプション、初期ON）**: 最後に、ひらがなを含む語の ぁぃぅぇぉっゃゅょゎ（その語の中の片仮名も）を大書きにする。片仮名だけの語（シャツ・チョウチョウ 等の外来語・片仮名表記）は変換の対象外なので、入力のまま残す。これで変わった語の status は `converted`（`unverified` の語は `unverified` のまま）。

### 2層: 辞書（data/dict.json）

```json
{
  "version": 1,
  "sources": { "fuhyo": { "title": "...", "url": "..." }, "wikt": { ... } },
  "entries": [
    { "modern": "きょう", "historical": "けふ", "kanji": "今日", "pos": "noun", "scan": true, "src": ["fuhyo", "wikt"] },
    { "modern": "かんがえる", "historical": "かんがへる", "kanji": "考える", "pos": "verb", "src": ["fuhyo", "wikt"] },
    { "modern": "どう", "historical": "どう", "pos": "adverb", "src": ["fuhyo"] }
  ]
}
```

- 変わらない語（どう・もう など）も、出典があれば `historical` に同じ形を入れて「確認済み」にする。
- 検索のしかた:
  - ひらがなだけのトークン: 表層形で引く。
  - 活用する語（動詞・形容詞）: 基本形（漢字でも仮名でも）と `kanji`/`modern` を照合し、基本形の読みの差分位置をトークンの読みに当てはめ、表層形の末尾の仮名部分だけを置き換える（考え→考へ、終わっ→終はっ）。
  - 漢字だけの語: 何もしない（漢字はそのまま）。
- `src` のない項目は入れない。各出典の詳細は sources.md。

### 未確認の判定

次のすべてに当てはまるトークン（またはその仮名部分）を `unverified` にする。

- 仮名を含み、規則・閉じた一覧・辞書のどれでも決まらなかった。
- 決まらなかった仮名部分に、歴史的仮名遣いで別の書き方がありうる仮名（い・う・え・お・わ・じ・ず、および長音「〜う」）を含む。
- 片仮名だけの語・記号・英数字・絵文字・URL は対象外（そのまま、確認済み扱い）。

動詞・形容詞の漢字＋送り仮名は、送り仮名のうち活用語尾を除いた部分（例: 終わる の「わ」、味わう の「わ」、一段動詞の「え／い」）で判定する。

## 画面

- 1カラム、スマホ幅（390px）優先。上から: 見出し → 入力欄 → 変換結果 → 文字数（n/280、超過で警告色）→ ボタン（コピー／Xで投稿）→ オプション（小書きを大書きにする、初期ON）→ 凡例（点線＝未確認）。
- 入力中に100ms程度まとめてから変換する。解析器の読み込み中は「辞書を読み込み中」を表示し、読み込み後に変換する。
- 結果の表示は segments を span に描き、`unverified` に点線の下線と title「未確認」をつける。
- コピー: `navigator.clipboard.writeText`、使えない環境は選択＋`execCommand('copy')`。
- Xで投稿: `https://x.com/intent/tweet?text=<encodeURIComponent(結果)>` を新しいタブで開く（2026-11-18 に docs.x.com で現行仕様を確認）。
- 文字数: X（twitter-text v3）の重みに合わせる。U+0000–U+10FF, U+2000–U+200D, U+2010–U+201F, U+2032–U+2037 は1、それ以外は2、絵文字は1つ2、URLは23。上限280。
- 見た目の詳細は frontend-design の段階で決める。
- オプションの状態は localStorage に保存（入力文は保存しない）。

## 公開

- GitHub に新規公開リポジトリ `kyukana-converter`、GitHub Actions で `vite build` → Pages へ配信。Vite の `base` は `/kyukana-converter/`。
- 余裕があれば PWA（manifest＋Service Worker で wasm を含めてキャッシュ）。

## テスト

- `tests/cases.json` に50件以上（出典付きを優先）。全件の合格数／件数を出す。
- 単体テスト: かな操作、規則、辞書引き、文字数。
- 画面は Playwright で 390×844 のスクリーンショットを撮り、目で確認する。

- 再分割の細かい条件の調整（テストを通しながら）。
